# METALAYER — Bellows

> Generated by agentic-control-kernel on 2026-05-03
> Customized for Bellows. Profile: governed.

This repository operates as a **control loop for an open-source Rust
framework**, governed by the
[agentic-control-kernel](../agentic-control-kernel/) metalayer.

**Core Law**: Do not grant an agent more mutation freedom than your
evaluator can reliably judge.

For Bellows specifically: contract changes (edits to `bellows-core`)
have the narrowest stability margin and the largest blast radius —
they ripple to every downstream user of the crate. The metalayer
enforces this with a contract-change shield (see
[.control/policy.yaml](.control/policy.yaml) §G6 + §shields).

## Control flow

```text
Plant: the Bellows repo + crates.io publish state
  → observe — CI gates (cargo check/test/clippy/fmt/deny), doc-xref audit
  → estimator — current `bellows-core` version, RF-* count, member count
  → belief b_t — state vector defined in .control/plant.yaml

  → LLM agent (via PR review or autonomous contributor) — proposes θ_t
  → controller (cargo + git + reviewer) — synthesizes proposed u_t
  → safety shields — contract_change_shield, workspace_dep_shield, license_shield
  → plant — apply u_t (merge to main, publish to crates.io)
  → evaluator/ledger — git log + crates.io history + this repo's PR record
```

## What this metalayer is NOT

- Not a runtime governing the *running* Bellows agents end users build.
  Bellows agents have their own sandbox + tool + approval story; that's
  per-workflow, not per-repo.
- Not a controller that rewrites this repo autonomously. Today, the
  metalayer is a structured docs+CI artifact — autonomous self-edit
  arrives only at v1.0 (see ROADMAP "autonomous" profile, currently
  inactive).

## Stability constraint

Following the broader Broomva ecosystem convention (see CLAUDE.md in
the parent workspace), **L3 governance changes have the narrowest
stability margin**. Edits to this file, `.control/policy.yaml`, and
`.control/plant.yaml` should be rare and deliberate. The correct
cadence: observe a recurring need across multiple PRs before
crystallizing a rule.
